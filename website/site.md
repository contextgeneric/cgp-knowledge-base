# The website: build, branches, example code, and navigation

This document records the facts every website task shares: how the site is built and deployed,
which branch carries the redesign, the `example-code` crate that compiles the pages' code, and the
navigation. Each page's own record is under [pages/](pages/README.md).

## How the site is built

**The site is a stock [Docusaurus](https://docusaurus.io/) v3 installation, kept stock on purpose.**
[docusaurus.config.ts](https://github.com/contextgeneric/contextgeneric.dev/blob/main/docusaurus.config.ts)
sets the production URL `https://contextgeneric.dev`; the classic preset supplies the docs, blog,
pages, sitemap, and SVGR plugins, and both docs and blog show last-updated times and "edit this page"
links. The sidebar in
[sidebars.ts](https://github.com/contextgeneric/contextgeneric.dev/blob/main/sidebars.ts) is
autogenerated from the `docs/` tree, so a page's position comes from its `sidebar_position` and its
directory's `_category_.json`. The project moved from Zola to Docusaurus to stop spending time on
theming and committed to no plugins and no React beyond the landing page, as the
[new-website post](blog/new-website.md) records; raise any new site machinery with the user.

**Three settings depart from stock, all to publish the agent skill from its own repository:**

- **`markdown.format: 'detect'`:** a `.md` file is parsed as CommonMark and only `.mdx` as MDX,
  because MDX reads an autolink such as `<https://example.com>` in the skill as JSX and fails the
  build. No page uses MDX-only syntax, so nothing else changed.
- **webpack `resolve.symlinks: false`,** set by a one-function inline plugin: the skill pages are
  symlinks into the submodule, and a resolved path no longer matches the metadata the docs plugin
  registered, so every such page fails to render.
- **The docs plugin excludes `**/cgp-skills/**`,** so the submodule's README and `AGENTS.md` do not
  become pages.

Both deploy workflows check out with `submodules: recursive`; without it the build fails on missing
files.

**The theme is the other departure, within the policy.** Colours, fonts, and code colours come from
tokens in `src/css/custom.css`, two Prism themes in `src/prism/themes.ts`, and configuration
options: `headTags` for the SVG favicon, the `@font-face` rules and the body font's preload, the
`theme-color` tags, the logo's `srcDark`, the announcement bar's colours, and
`prism.additionalLanguages`. It adds no plugin and swizzles no component.
[visual-design.md](visual-design.md) records the palette, fonts, and contrast check.

**GitHub Actions deploys the site.** The workflows in
[.github/workflows/](https://github.com/contextgeneric/contextgeneric.dev/tree/main/.github/workflows)
build it and publish to GitHub Pages, with the domain in
[static/CNAME](https://github.com/contextgeneric/contextgeneric.dev/blob/main/static/CNAME). Install
with `npm ci`; `npm start` runs the dev server and `npm run build` the static output, as the
repository's [README](https://github.com/contextgeneric/contextgeneric.dev/blob/main/README.md)
records.

**`onBrokenLinks` and `onBrokenAnchors` are both `throw`.** A dangling link or heading anchor fails
the build, so a change that renames or moves a page or heading fixes every reference in the same
change. The MDX setup rejects `{#custom-id}`, so anchors always come from heading text.

## Branches, and what is not on `main`

**Every push to `main` deploys, so unpublished work lives on a branch named after the release it
accompanies.** `v0.8.0` carries the whole redesign and merges when the release ships. It carries
two releases, `cgp` v0.8.0 and `cargo-cgp` v0.1.0, merges only once both are published, and every
page on it treats both as out.

Two other branches hold content that is not on `main`:

- **`incoherent-rust`:** an unpublished blog post, recorded in
  [blog/incoherent-rust-today.md](blog/incoherent-rust-today.md).
- **`rustlab-presentation`:** the slide assets for the RustLab talk transcript.

The `notes/` tree, on `main` and `v0.8.0`, is working notes on applying Diátaxis to the site and on
implicit parameters. Nothing under it is routed or built; its conclusions belong in the
[writing guides](writing-guides/README.md).

## The example-code crate

**`example-code/` is a test-only Rust crate that compiles the code the site shows; it is not part of
the site.** Docusaurus never sees it and no page links it. Its code lives under `tests/` as one
integration-test binary per `docs/` section (`tests/concepts_tests.rs` pulls in the module tree
`tests/concepts/`), one file per page in `snake_case`
(`docs/concepts/coherence.md` against
[`tests/concepts/coherence.rs`](https://github.com/contextgeneric/contextgeneric.dev/blob/main/example-code/tests/concepts/coherence.rs)),
and one module per page heading in the page's order. A page that shows no code gets no file.
`cargo test` in that directory is the check; `cargo test --no-run` is the fast half, since
`cargo check` skips integration tests.

The crate's [README](https://github.com/contextgeneric/contextgeneric.dev/blob/main/example-code/README.md)
holds its conventions. Four matter from this side:

- **Elided bodies are filled in,** each with a comment saying so; a body may differ from the page,
  but a signature, bound, attribute, or wiring line that differs is a defect.
- **Rejected snippets are `trybuild` compile-fail fixtures** under `tests/compile_fail/`, each a
  complete failing program with a blessed `.stderr`. Re-bless with
  `TRYBUILD=overwrite cargo test --test compile_fail_tests` after a toolchain or `cgp` change. A
  snapshot that quotes a `cgp` file holds that checkout's absolute path, so another checkout fails it
  until re-blessed.
- **Duplication between files is wanted,** because each file answers for its page alone.
- **Generated code is only shape-checked here;** `cargo cgp expand` on the test target is the
  authority on its text.

**A page gets its file when someone writes, revises, or reviews it,** so a missing file means nobody
has been through the page, per
[AGENTS.md](https://github.com/contextgeneric/contextgeneric.dev/blob/main/AGENTS.md#code). On
`v0.8.0` the targets are `tests/concepts/` (every concept page with code), `tests/comparisons/`
(every comparison page), `tests/tutorials/` (the ported tutorial parts), the standalone binaries
`tests/quickstart.rs`, `tests/overview.rs`, and `tests/front_page.rs`, `tests/cargo_cgp/`, and
`tests/reference/`, which mirrors `errors.rs`, `macros/`, `attributes/`, `derives/`, `traits/`,
`providers/` (every page with code), `components/` with `handler/`, and `types/`. The `traits/` and
`types/` mirrors stay flat, because a Rust module name cannot hold a hyphen; every basename is
unique, so the mirror still resolves.

**The crate takes `cgp` from the `cgp` repository's git `main`,** the 0.8.0 release the site
documents, so it tests the pages before the release reaches crates.io; pinning `cgp = "0.8.0"` joins
the tutorials' pin on the release checklist.

Two sets of capture-only programs sit outside the test suite and CI, compiled by the diagnostic
capture harness with cargo-cgp's pinned nightly:

- **`example-code/diagnostics/cgp_serde/`:** the cgp-serde debugging guide's failing programs (a
  missing byte-vector entry, an iterator-reference entry, JSON error wiring, and a fixed-size array
  key the macro parser rejects), which need cgp-serde's dependencies.
- **`example-code/diagnostics/reference/shared_missing_name.rs`:** the compile-errors page's merged
  failure, three checked components needing one missing field; the harness requires all three check
  entries and both secondary labels.

Other Projects examples are checked in their project checkouts.

## Navigation, sidebar order, and the announcement bar

**The navigation bar carries Tutorials, Docs, Blog, and AI, plus a GitHub link.** The footer repeats
the docs entry points (the Introduction, the Quickstart, the Overview, and the Tutorials) beside
GitHub Discussions, [Discord](https://discord.gg/Hgk3rCw6pQ), and the
[r/cgp subreddit](https://www.reddit.com/r/cgp/). The site is licensed CC BY-SA 4.0.

**The `docs/` sidebar order is settled:** Introduction, Quickstart, Overview, Tutorials, Concepts
(5), Comparisons (6), Reference (7), Projects (8), `cargo-cgp` (9), Resources (10), Contribute (11),
and AI (12), as
[information-architecture.md](information-architecture.md#navigation-and-sidebar-order) wants.

**The announcement bar is hardcoded in `docusaurus.config.ts`,** so it is updated by hand with every
release announcement. On `main` it promotes the v0.7.0 post; `v0.8.0` points it at the v0.8.0 post.
Its one-line pitch is governed by [identity.md](../communication-strategy/identity.md).

**The configured tagline on `main` is the retired "Modular programming paradigm for Rust."**
`v0.8.0` carries the current line from [identity.md](../communication-strategy/identity.md), *"a
language extension for Rust, with pluggable trait implementations at compile-time,"* which reaches
the live site when the branch merges.
