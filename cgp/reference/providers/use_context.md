# `UseContext`

`UseContext` is a zero-sized provider that implements a component's provider trait by forwarding
each method back to the context's own consumer-trait implementation.

## Purpose

`UseContext` turns what a context already does into a provider that other providers can call. Wiring
or passing `UseContext` for a trait means "use whatever this context does for this trait."

It is the dual of the consumer blanket impl. The consumer blanket impl implements `CanGreet` for a
context by calling the provider trait `Greeter` on the context's wired provider. `UseContext` goes
the other way: it implements `Greeter` by calling the context's `CanGreet`.

Its main use is as the inner provider of a
[higher-order provider](../../concepts/higher-order-providers.md). A higher-order provider takes
another provider as a parameter, and `UseContext` lets that inner provider be "whatever the context
wires." A struct that defaults its inner parameter to `UseContext` falls back to the context's
wiring unless the wiring names an inner provider.

## Definition

`UseContext` is a unit struct defined in `cgp-component` and exported by the prelude:

```rust
pub struct UseContext;
```

Every impl it has is generated by `#[cgp_component]`. The alias
`WithContext = WithProvider<UseContext>`, also in the prelude, is covered under
[`WithProvider`](with_provider.md).

## Behavior

`#[cgp_component]` emits a `UseContext` impl of the provider trait for every component. It requires
the context to implement the consumer trait and forwards each method to it. For this component:

```rust
#[cgp_component(Greeter)]
pub trait CanGreet {
    fn greet(&self);
}
```

the impl is:

```rust
impl<__Context__> Greeter<__Context__> for UseContext
where
    __Context__: CanGreet,
{
    fn greet(__context__: &__Context__) {
        __Context__::greet(__context__)
    }
}
```

The impl is paired with an `IsProviderFor` impl carrying the same `where` clause, so the
[check traits](../../concepts/check-traits.md) report a missing consumer implementation. The
consumer trait's supertraits are reproduced in the `where` clause.

A context must never wire a component to `UseContext` for the same trait instance it is resolving.
The context would implement `CanGreet` through `UseContext`, which implements `Greeter` by calling
`CanGreet`: a cycle the trait solver cannot resolve, reported as an overflow or an unsatisfied
bound. The same cycle arises when a higher-order provider with inner `UseContext` asks the context
for the very instance the provider is serving. `UseContext` is safe when it reaches a different
instance, such as the same component at another type argument.

## Examples

This higher-order provider scales the area of an inner shape and asks the context for that inner
area:

```rust
use cgp::prelude::*;

#[cgp_component(AreaCalculator)]
pub trait CanCalculateArea<Shape> {
    fn area(&self, shape: &Shape) -> f64;
}

pub struct Rectangle {
    pub width: f64,
    pub height: f64,
}

pub struct Scaled<Shape> {
    pub shape: Shape,
    pub factor: f64,
}

#[cgp_impl(new RectangleArea)]
impl AreaCalculator<Rectangle> {
    fn area(&self, shape: &Rectangle) -> f64 {
        shape.width * shape.height
    }
}

pub struct ScaledArea<InnerCalculator = UseContext>(pub PhantomData<InnerCalculator>);

#[cgp_impl(ScaledArea<InnerCalculator>)]
#[use_provider(InnerCalculator: AreaCalculator<Shape>)]
impl<Shape, InnerCalculator> AreaCalculator<Scaled<Shape>> {
    fn area(&self, shape: &Scaled<Shape>) -> f64 {
        InnerCalculator::area(self, &shape.shape) * shape.factor * shape.factor
    }
}

pub struct App;

delegate_components! {
    App {
        open AreaCalculatorComponent;

        @AreaCalculatorComponent.Rectangle: RectangleArea,
        @AreaCalculatorComponent.<Shape> Scaled<Shape>: ScaledArea,
    }
}
```

`App` wires `Scaled<Shape>` to `ScaledArea`, whose inner calculator defaults to `UseContext`. For a
`Scaled<Rectangle>`, the inner call asks `App` for `CanCalculateArea<Rectangle>`, a different
instance, which `App` answers with `RectangleArea`. Because the inner call goes back through the
context, nesting works too: a `Scaled<Scaled<Rectangle>>` scales twice. Writing
`ScaledArea<RectangleArea>` in the entry would instead fix the inner calculator and bypass the
context's wiring.

## Related constructs

These constructs are the ones `UseContext` works with:

- [`#[cgp_component]`](../macros/cgp_component.md): generates its impl and the consumer blanket impl
  it mirrors.
- [Higher-order providers](../../concepts/higher-order-providers.md) and
  [`#[use_provider]`](../attributes/use_provider.md): the pattern it serves and the attribute that
  binds the inner provider.
- [Dispatch combinators](dispatch_combinators.md): `MatchWithValueHandlers` defaults its per-variant
  provider to `UseContext`, as the [extensible shapes](../../../examples/extensible-shapes.md)
  example shows.
- [`WithProvider`](with_provider.md): the adapter behind the `WithContext` alias.
- [`RedirectLookup`](redirect_lookup.md): the other provider every component gets, which routes
  through a table instead of back to the context.
- [`IsProviderFor`](../traits/is_provider_for.md): carries its dependency to the checks.
