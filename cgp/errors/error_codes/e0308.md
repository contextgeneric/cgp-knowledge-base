# E0308: mismatched types

`E0308` is Rust's diagnostic for an expression whose type differs from the type its position
expects, such as a call argument of another type than the parameter it fills.

## What it means

The compiler prints "mismatched types", a caret on the expression labelled
``expected `A`, found `B` ``, and, for a call argument, a note pointing at the function's definition
("method defined here"). The error index states it plainly: "Expected type did not match the received
type." It occurs when an expression is used where the compiler expects an expression of a different
type, most commonly a function or method argument of another type than the parameter declares.

## The rule behind it

Every expression in a typed position must have that position's type, modulo the coercions the
language allows. The rule is type checking itself, described in the
[Rust reference on type coercions](https://doc.rust-lang.org/reference/type-coercions.html) and the
[expressions chapter](https://doc.rust-lang.org/reference/expressions.html). Where a method call's
receiver has exactly one applicable impl of the trait that declares the method, the compiler commits
to that impl and checks the arguments against its signature, so a call meant for another impl
reports its argument as the mismatch rather than the missing impl.

## Where CGP produces it

CGP produces it where a call resolves to the one impl an extensible-data operation leaves, so the
argument that named another impl is the mismatch:

- [Extensible data](../data/extensible-data.md): `extract_field` on a remainder that already ruled
  a variant out. The remainder implements `ExtractField` only for the variants it may still yield,
  so the compiler commits to the other one and reports the tag argument, the label comparing the two
  tags' `Symbol` lengths (``expected `9`, found `6` ``).
