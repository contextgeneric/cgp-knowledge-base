# E0782: a trait where a type belongs

`E0782` is Rust's diagnostic for a trait written bare where a type is expected, which the 2021 and
later editions reject.

## What it means

The compiler prints "expected a type, found a trait", with the caret on the trait's name, and a
`help:` offering to add `dyn` to make the name a trait object. It arises wherever a bare trait name
stands in a type position: a parameter type, a generic argument, an impl's `Self` or trait argument.

## The rule behind it

A trait object type is written `dyn Trait`. Editions before 2021 also accepted the bare `Trait` for
it, and the 2021 edition made the bare form an error, so a bare trait in a type position is
rejected rather than read as a trait object, per the error index and the
[Rust reference on trait objects](https://doc.rust-lang.org/reference/types/trait-object.html). The
check runs when the compiler lowers the written types, so the error carries no obligation chain.
The `dyn` suggestion is the fix only when the code means a trait object.

## Where CGP produces it

- [Unresolved wiring name](../wiring/unresolved-wiring-name.md): a consumer trait written as a
  `delegate_components!` key where its component marker belongs. The key becomes a generic argument
  of `DelegateComponent`, so the trait stands in a type position, and the `dyn` suggestion is wrong
  there. `cargo-cgp` reshapes it into `[CGP-E040]`, naming the component; see the
  [cargo-cgp error-code catalog](../../../cargo-cgp/error-code.md).
