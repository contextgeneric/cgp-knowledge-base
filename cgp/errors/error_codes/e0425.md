# E0425: an identifier is not found in this scope

`E0425` is Rust's diagnostic for an identifier that resolves to nothing in the scope where it is
used, reported without the path context that would make it an [`E0433`](e0433.md).

## What it means

The compiler prints "cannot find type `Name` in this scope" (or the value/function variant) with the
bare label `not found in this scope` under the caret. It covers an unresolved name the compiler met
on its own rather than as the head of a qualified path: a variable or type that was never declared,
one whose declaration is out of scope, or a name a macro emitted that no item binds. When a
similarly named binding exists, `rustc` adds a `help:` naming it.

## The rule behind it

Rust resolves every identifier against the bindings visible at its use site (items, imports, generic
parameters, and local bindings) and an identifier with no such binding is a resolution error rather
than a type error. As with `E0433`, this happens during name resolution, before any bound is
evaluated, so no obligation chain accompanies it; the mechanism is the one described in the
[Rust reference on names and scopes](https://doc.rust-lang.org/reference/names/scopes.html).

The split against [`E0433`](e0433.md) is the practical thing to know: the two carry the *same*
"cannot find type" headline and differ only in the code and the trailing label, so they must be
searched for separately. In CGP's generated code the distinction tracks how the compiler reached the
name: a path used as a type or a qualifier fails as `E0433`, while a bare name the compiler looked
up with no path context fails as `E0425`.

## Where CGP produces it

- [Wrong component half](../lowering/wrong-component-half.md): a **`#[cgp_impl]` header naming a
  trait that is not a component's provider trait**, the component's consumer trait where its
  provider trait belongs, or a trait that is no CGP component at all. The macro derives the
  component marker from the trait name, so the expansion references a `…Component` type nothing
  declares, and the compiler reports ``cannot find type `GreetComponent` in this scope`` with the
  caret on the attribute. It arrives inside a burst of further lowering errors
  ([`E0107`](e0107.md), `E0186`, [`E0207`](e0207.md)), which is why `cargo-cgp` reshapes the whole
  cascade into a single `[CGP-E032]`/`[CGP-E033]` error on the misused trait name.
- [Undeclared dependency](../lowering/undeclared-dependency.md): a **bare abstract type such as
  `Error` written without its `#[use_type]` import**. Nothing rewrites the name into the context's
  associated type, so the compiler reports ``cannot find type `Error` in this scope`` and suggests
  importing `std::error::Error` and its namesakes, none of which is the fix. `cargo-cgp` reshapes it
  into `[CGP-E035]` when a requirement of the component names the trait that declares the type.
- [Unresolved wiring name](../wiring/unresolved-wiring-name.md): a **wiring key or value that names
  nothing in scope**, such as a component not imported, a key guessed from a trait's name, or a
  provider never declared (often a `#[cgp_impl]` written without `new`). The suggestions rustc adds
  (a type parameter, a similarly named trait) do not fit a wiring entry, which is why `cargo-cgp`
  reshapes it into `[CGP-E038]` or `[CGP-E041]` to `[CGP-E044]`.
