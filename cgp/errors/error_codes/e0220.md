# E0220: associated type not found

`E0220` is Rust's diagnostic for an associated type named on a trait or a type parameter that
declares no associated type of that name.

## What it means

The compiler prints "associated type `Name` not found for `T`", labelled "associated type `Name`
not found", with the caret on the name. It covers two uses: a type-relative path such as `T::Name`
or `Self::Name`, where the traits bounding `T` declare no `Name`, and an associated-type binding
such as `Trait<Name = i32>`, where `Trait` declares no `Name`. Both are a misspelling, an item that
lives on another trait, or a bound the type parameter lacks.

## The rule behind it

An associated type is named through the trait that declares it, `<T as Trait>::Name`, and when `T`
is a type parameter the shorter `T::Name` is accepted too, per the
[Rust reference on associated types](https://doc.rust-lang.org/reference/items/associated-items.html#associated-types).
The short form names no trait, so the compiler looks for `Name` among the associated types of the
traits that bound `T` in scope, its declared bounds and `where` clauses with their supertraits. A
parameter that carries no bound declaring `Name` leaves the path with nothing to resolve to. The
split against [`E0576`](e0576.md) is the useful thing to know: `E0576` reports a fully qualified
path into a named trait that lacks the item, while `E0220` reports a short path whose parameter
carries no bound declaring it.

## Where CGP produces it

- [Undeclared dependency](../lowering/undeclared-dependency.md): `Self::Error` in a `#[cgp_fn]`,
  `#[cgp_impl]`, or `#[cgp_component]` definition that does not import the abstract type with
  `#[use_type(HasErrorType.Error)]`, so the generated context (`__Context__`, or `Self`) carries no
  `HasErrorType` bound. `cargo-cgp` reshapes it into `[CGP-E035]`; see the
  [cargo-cgp error-code catalog](../../../cargo-cgp/error-code.md).
