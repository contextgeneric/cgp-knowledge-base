# E0107: wrong number of generic arguments

`E0107` is Rust's diagnostic for an item named with more or fewer generic arguments than it declares
parameters.

## What it means

The compiler prints "trait takes 0 generic arguments but 1 generic argument was supplied" (or the
struct, function, or lifetime variant) when the use gives too many, with a `help:` to remove the
unnecessary generics, and "missing generics for trait `Name`", labelled "expected 1 generic
argument", when it gives too few, with a `help:` to add the missing argument. A note points at the
item's definition and states how many parameters it declares. The caret sits on the item's name
where it is used.

## The rule behind it

Every use of a generic item must supply arguments that match the parameters its declaration lists:
a struct, a trait, or a function declared with two type parameters takes two type arguments
wherever it is named with arguments. The error index illustrates the rule for types, functions, and
lifetime arguments. The check runs when the compiler lowers the written types into its own
representation, before any trait bound is evaluated, so no obligation chain accompanies it; the
declarations it compares against are the generic parameters described in the
[Rust reference on generics](https://doc.rust-lang.org/reference/items/generics.html).

## Where CGP produces it

- [Wrong component half](../lowering/wrong-component-half.md): the CGP macros write the context as
  the leading argument of a provider trait and leave it out of a consumer trait, so naming the other
  half gives the trait one argument too many (a consumer trait in a `#[cgp_impl]` header or a
  `#[use_provider]` bound, or a trait that is not a component under `#[cgp_impl]`) or one too few
  (a provider trait in `#[uses]`). `cargo-cgp` reshapes each into `[CGP-E032]`, `[CGP-E033]`,
  `[CGP-E034]`, or `[CGP-E037]`; see the
  [cargo-cgp error-code catalog](../../../cargo-cgp/error-code.md).
