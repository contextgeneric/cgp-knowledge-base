# E0477: the type does not fulfill the required lifetime

`E0477` is Rust's diagnostic for a type that must outlive a lifetime it does not outlive, such as a
type with a lifetime parameter required to be `'static`.

## What it means

The compiler prints "the type `T<'a>` does not fulfill the required lifetime", with a caret on the
place that required it. The error index describes it as "The type does not fulfill the required
lifetime", and marks the code as no longer emitted by the compiler; stable `rustc` and the nightly
`cargo-cgp` pins still emit it for the CGP case below, so the code is listed here as the compiler
prints it.

## The rule behind it

A bound `T: 'b` holds only when every lifetime in `T` outlives `'b`. A bound quantified over every
lifetime (`for<'b> …`) whose proof needs `T: 'b` therefore holds only for a `T` that outlives every
lifetime, a `'static` one. The outlives rules and the higher-ranked bounds are described in the
[Rust reference on trait and lifetime bounds](https://doc.rust-lang.org/reference/trait-bounds.html).

## Where CGP produces it

- [Extensible data](../data/extensible-data.md): a bound on an enum's borrowed field view for every
  lifetime (`for<'b> Value::FieldsRef<'b>: Debug`), checked for an enum with a lifetime parameter.
  `FieldsRef<'b>` declares `where Self: 'b`, so the bound asks the enum to outlive every lifetime.
