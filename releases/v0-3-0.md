# CGP v0.3.0

The first release after the public launch, and the one that added abstract types, the getter macros,
and error wrapping. Three of its five headline features are still current in substance; the syntax
that carried them is not.

- **Tag** — [`v0.3.0`](https://github.com/contextgeneric/cgp/releases/tag/v0.3.0), 8 January 2025
- **Announcement** — [CGP Updates: v0.3.0 Release and New Chapters](https://contextgeneric.dev/blog/v0-3-0-release),
  documented at [website/blog/v0-3-0-release.md](../website/blog/v0-3-0-release.md)
- **Changelog** — [v0.3.0](https://github.com/contextgeneric/cgp/blob/main/CHANGELOG.md)
- **Relation to today** — the capabilities survive; every macro spelling in the announcement has
  changed.

## What it introduced

**Abstract types get a dedicated declaration.** The `cgp_type!` function-like macro collapses an
abstract-type trait into one line, expanding into a `#[cgp_component]` trait plus a `UseType` blanket
impl, and `HasErrorType` and `HasRuntimeType` are redefined in terms of it. This is the release where
CGP's answer to "abstract over a type, not just an implementation" becomes ergonomic rather than
hand-written.

**Getters get two macros.** `#[cgp_auto_getter]` generates a blanket getter impl over `HasField`,
keyed by the method name, so any context with a matching field implements the trait with no wiring.
`#[cgp_getter]` extends `#[cgp_component]` instead, making the getter a full component whose source
field is chosen at wiring time, and derives `UseFields` and `UseField` impls for it. The announcement
records that both were prompted by user feedback that direct `HasField` use was too complex for
beginners — the first instance of the ergonomics pressure that shaped every release since.

**Error handling is reorganized.** `CanWrapError` arrives to replace the previous idiom of raising a
tuple, `CanRaiseError<(Self::Error, Detail)>`. The `Async` bound is dropped from
`HasErrorType::Error` and re-added separately as `HasAsyncErrorType`. Generic `ErrorRaiser` providers
move into `cgp-error`, the generic ones into a new `cgp-error-extra`, and `ErrorWrapper` is
implemented across the existing backends. The `cgp-error-anyhow` crate is published, completing the
set beside `cgp-error-eyre` and `cgp-error-std`.

**Runtimes get an interface.** The new `cgp-runtime` crate introduces `HasRuntimeType` and
`HasRuntime`, giving generic code an abstract runtime to program against.

Two structural changes round it out: the macro crates stop being dependencies of the library crates
they generate for, and crate exports are tightened — submodules made private, items exported
explicitly rather than by glob.

## What it changed or removed

`HasErrorType::Error` loses its `Async` bound, which is why `HasAsyncErrorType` had to be introduced.
`cgp-inner` moves out of `cgp-core` into `cgp-extra`. Nothing is deleted.

## How it relates to v0.8.0

**Still current in substance.** [`HasErrorType`](../cgp/reference/components/has_error_type.md),
[`CanRaiseError` and `CanWrapError`](../cgp/reference/components/can_raise_error.md), the
[error providers](../cgp/reference/providers/error_providers.md),
[`HasRuntime` / `HasRuntimeType`](../cgp/reference/components/has_runtime.md),
[`#[cgp_auto_getter]`](../cgp/reference/macros/cgp_auto_getter.md), and
[`#[cgp_getter]`](../cgp/reference/macros/cgp_getter.md) all exist and work as this release described
them. The whole of [modular error handling](../cgp/concepts/modular-error-handling.md) rests on what
landed here, and `cgp-error-anyhow` is still the backend most CGP applications reach for.

**Renamed or restructured.** `cgp_type!` became the attribute
[`#[cgp_type]`](../cgp/reference/macros/cgp_type.md) in [v0.4.0](v0-4-0.md), which also changed the
names it generates: the announcement's `ErrorTypeComponent` and `ProvideErrorType` are now
`ErrorTypeProviderComponent` and the built-in provider trait
[`TypeProvider`](../cgp/reference/components/has_type.md), the latter renamed from `ProvideType` in
[v0.7.0](v0-7-0.md).

**Removed.** `HasAsyncErrorType` was deleted in [v0.5.0](v0-5-0.md) along with the `Async` trait it
existed to apply; the `Send` guarantee it provided is now recovered where it is needed, per
[send-bounds](../cgp/concepts/send-bounds.md). `HasComponents`, which the announcement's
`#[cgp_getter]` example implements by hand, was renamed twice in [v0.4.0](v0-4-0.md) and removed in
[v0.6.0](v0-6-0.md).

**Demoted.** The getter macros are still correct but are no longer the default way to read a context
field. [`#[implicit]`](../cgp/reference/attributes/implicit.md) arguments, added in
[v0.7.0](v0-7-0.md), cover the common case, and
[reading-context-fields](../cgp/guides/reading-context-fields.md) names the three narrower cases a
getter trait still earns. `UseFields`, which the announcement wires directly, is likewise now a
fallback rather than a first choice.
