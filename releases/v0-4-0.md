# CGP v0.4.0

The release that made CGP debuggable, and the largest in the history by change count. It introduces
the `IsProviderFor` technique that still underpins every readable CGP error, alongside the preset
system and `#[cgp_context]` — two constructs that have since been deleted.

- **Tag** — [`v0.4.0`](https://github.com/contextgeneric/cgp/releases/tag/v0.4.0), 9 May 2025
- **Announcement** — [CGP v0.4.0 Release: Unlocking Easier Debugging, Extensible Presets, and More](https://contextgeneric.dev/blog/v0-4-0-release),
  documented at [website/blog/v0-4-0-release.md](../website/blog/v0-4-0-release.md)
- **Changelog** — [v0.4.0](https://github.com/contextgeneric/cgp/blob/main/CHANGELOG.md), thirty-odd
  entries across six categories
- **Relation to today** — the debugging machinery is current and load-bearing; the preset and context
  machinery is gone.

## What it introduced

**The debugging breakthrough is the headline, and it is still how CGP works.** Before this release an
unsatisfied dependency produced an error with the cause hidden, and the
[launch post](../website/blog/early-preview-announcement.md) had proposed fixing it by patching
`rustc`. v0.4.0 found a way to do it in the library. `IsProviderFor<Component, Context, Params>` is an
empty marker trait carried as a supertrait on every provider trait and implemented for each provider
under the *same* `where` bounds it used to implement the provider trait — so when a dependency is
unmet, the compiler names it instead of swallowing it. `CanUseComponent` is the context-side
companion, and `check_components!` turns both into a compile-time assertion. Because the technique
needs the provider's bounds captured at the definition site, provider impls had to become annotated,
which is why `#[cgp_provider]` and `#[cgp_new_provider]` became mandatory here.
`delegate_and_check_components!` fuses the two steps for simple cases.

**Presets arrive.** `cgp_preset!` defines a reusable, mergeable group of component wirings as a
module, with `#[cgp::re_export_imports]` capturing the imports the merge needs, an `override` keyword
for conflicting entries, multiple inheritance between presets through macro-level key copying, and
single inheritance into a context. The announcement frames it as merging type-level lookup tables and
compares it to prototypal rather than class-based inheritance.

**`#[cgp_context]` arrives** to generate a context's provider struct and its `HasCgpProvider` impl,
reducing a context definition to one attribute.

**Datatype-generic programming begins.** `#[derive(HasFields)]` and the `HasFields`, `HasFieldsRef`,
`FromFields`, `ToFields`, and `ToFieldsRef` traits let a provider see a struct's whole field list as a
type-level product, without knowing the concrete type. The Greek-letter abbreviations (`π`, `ω`, `ι`,
`ε`) are introduced at the same time to keep those types readable in errors.

Several smaller improvements matter. `cgp_type!` becomes the attribute `#[cgp_type]`, with new default
naming. `#[cgp_component]` gains the short positional form and support for associated `const` items.
The getter macros learn `&str`, `Option<&T>`, and slice returns, generic parameters, and a
`PhantomData` disambiguator, and gain getter combinators for nested fields. `#[blanket_trait]` is
added for trait aliases — briefly named `#[trait_alias]` within the same release.
`delegate_components!` learns to define new structs inline with `new`. And `UseContext` is derived
automatically inside `#[cgp_component]`.

## What it changed or removed

`HasComponents` is renamed **`HasProvider`** and then **`HasCgpProvider`** within this one release.
`#[new_cgp_provider]` is renamed `#[cgp_new_provider]`, and `#[trait_alias]` is renamed
`#[blanket_trait]`. The `'static` bound is dropped from the `Async` trait alias, since experience
showed it was rarely needed and blocked instantiating abstract types with borrowed concrete ones.
Nothing is deleted outright.

## How it relates to v0.8.0

**Still current and central.** [`IsProviderFor`](../cgp/reference/traits/is_provider_for.md),
[`CanUseComponent`](../cgp/reference/traits/can_use_component.md),
[`check_components!`](../cgp/reference/macros/check_components.md), and
[`delegate_and_check_components!`](../cgp/reference/macros/delegate_and_check_components.md) work as
described, and the reasoning behind them is [check traits](../cgp/concepts/check-traits.md). The whole
error story this release opened continues in [`cargo-cgp`](../cargo-cgp/README.md), which rewrites
these diagnostics, and in the [error catalog](../cgp/errors/README.md), which classifies them. The
datatype-generic traits — [`HasFields`](../cgp/reference/traits/has_fields.md), `HasFieldsRef`,
`FromFields`, `ToFields`, `ToFieldsRef` — all still exist, as do
[`#[cgp_type]`](../cgp/reference/macros/cgp_type.md),
[`#[blanket_trait]`](../cgp/reference/macros/blanket_trait.md),
[`ChainGetters`](../cgp/reference/providers/chain_getters.md), the associated-`const` support, and the
positional `#[cgp_component(Greeter)]` form.

**Removed.** The **preset system in its entirety** — `cgp_preset!`, `#[cgp::re_export_imports]`,
`IsPreset`, `override`, and the `#[wrap_provider]` attribute added in [v0.4.1](v0-4-1.md) — was
deleted in [v0.8.0](v0-8-0.md) and replaced by [namespaces](../cgp/concepts/namespaces.md). The reason
is recorded in the [v0.8.0 draft announcement](../website/blog/v0-8-0-release.md): a context could
inherit only one preset because of coherence, and the macro-based multiple inheritance was fragile
because macros cannot see types. **`#[cgp_context]`** was deprecated in [v0.6.0](v0-6-0.md) and
removed in [v0.7.0](v0-7-0.md), and **`HasCgpProvider`** was removed in [v0.6.0](v0-6-0.md) — a
context now implements [`DelegateComponent`](../cgp/reference/traits/delegate_component.md) directly,
so the `{Context}Components` struct this release introduced no longer exists.

**Renamed since.** `Char` became [`Chars`](../cgp/reference/types/chars.md) and the `ι` abbreviation
became `ζ` in [v0.5.0](v0-5-0.md), the latter to avoid `rustc`'s `confusable_idents` warning. The
`Async` trait this release relaxed was removed outright in [v0.5.0](v0-5-0.md).

**Demoted.** [`#[cgp_provider]` and `#[cgp_new_provider]`](../cgp/reference/macros/cgp_provider.md)
still work and still derive `IsProviderFor`, but [`#[cgp_impl]`](../cgp/reference/macros/cgp_impl.md)
superseded them in [v0.6.0](v0-6-0.md) as the form to write; see
[writing-providers](../cgp/guides/writing-providers.md). The `check_components!` syntax changed in
[v0.7.0](v0-7-0.md) from `CanUsePerson for Person { ... }` to a bare context name with an optional
`#[check_trait(...)]` attribute.
