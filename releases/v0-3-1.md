# CGP v0.3.1

A three-item patch release, eight days after [v0.3.0](v0-3-0.md). Two of its three items were removed
in [v0.5.0](v0-5-0.md), which makes it the shortest-lived release in the history and a good
illustration of how thoroughly the `Async` experiment was reversed.

- **Tag** — [`v0.3.1`](https://github.com/contextgeneric/cgp/releases/tag/v0.3.1), 16 January 2025
- **Announcement** — none. No blog post covers this release; the next post is the
  [v0.4.0 announcement](../website/blog/v0-4-0-release.md) four months later.
- **Changelog** — [v0.3.1](https://github.com/contextgeneric/cgp/blob/main/CHANGELOG.md)
- **Relation to today** — almost entirely superseded.

## What it introduced

Three changes, all small. The minimum supported Rust version moves to **1.84**. `HasAsyncErrorType`
is added to the prelude, having been introduced in [v0.3.0](v0-3-0.md) but left unexported. And
`CanRaiseAsyncError` and `CanWrapAsyncError` are added to `cgp-error` and the prelude, completing the
async-flavoured mirror of the error components: where `CanRaiseError` raised into any error type,
these raised into one guaranteed `Send + Sync`, so that a future capturing the result stayed
spawnable.

## What it changed or removed

Nothing was removed. The MSRV bump is the only change to existing behavior.

## How it relates to v0.8.0

**Two of the three items no longer exist.** `HasAsyncErrorType`, `CanRaiseAsyncError`, and
`CanWrapAsyncError` were all deleted in [v0.5.0](v0-5-0.md), together with the `Async` trait they were
built on. The reasoning is worth understanding rather than just recording: these traits existed so
that a future returned by a generic async method would satisfy `tokio::spawn`'s `Send` bound, which
meant sprinkling `Send + Sync` through code that had no other reason to care. v0.5.0 found a way to
recover the guarantee at the point of use instead — a proxy trait implemented on the concrete context,
where the trait solver can see through to the real types — so the pervasive bounds became
unnecessary. That pattern is documented as
[recovering `Send` bounds](../cgp/concepts/send-bounds.md), and the components it produces are
[`CanRun` / `CanSendRun`](../cgp/reference/components/runner.md).

The surviving components are [`CanRaiseError` and `CanWrapError`](../cgp/reference/components/can_raise_error.md)
in their plain form, which never carried the `Async` bound and are what current code uses.

**The MSRV has moved on** to 1.89, set in [v0.5.0](v0-5-0.md) and unchanged since.

Code pinned to v0.3.1 that uses the async error aliases migrates by deleting the `Async` from each
name and, where a `Send` future is genuinely required, adding a proxy trait on the concrete context.
The [v0.5.0 announcement](../website/blog/v0-5-0-release.md) walks that migration, and notes the
fallback of copying the old definitions into a local crate for a codebase not ready to move.
