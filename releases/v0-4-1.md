# CGP v0.4.1

A small release with one large consequence: the `cgp-handler` crate, which introduces the
`Handler`/`Computer`/`Producer` family that most of CGP's later abstractions are built on. It was
written to unblock [Hypershell](../projects/hypershell/README.md), and everything downstream of it —
pipelines, visitors, builders, monadic composition — descends from this one addition.

- **Tag** — [`v0.4.1`](https://github.com/contextgeneric/cgp/releases/tag/v0.4.1), 14 June 2025
- **Announcement** — [CGP v0.4.1 Release: new cgp-handler crate, improved preset macros, and more](https://contextgeneric.dev/blog/v0-4-1-release),
  documented at [website/blog/v0-4-1-release.md](../website/blog/v0-4-1-release.md)
- **Changelog** — [v0.4.1](https://github.com/contextgeneric/cgp/blob/main/CHANGELOG.md); note the
  changelog dates it 2025-05-24 while the tag says 2025-06-14, and the tag is authoritative
- **Relation to today** — the handler family is current and has grown; the preset machinery around it
  is gone.

## What it introduced

**The `cgp-handler` crate** defines three components sharing one shape. `Handler` is the general
asynchronous, fallible operation; `Computer` is the pure synchronous transform; `Producer` produces a
value from nothing but its context. All three carry a phantom `Code` parameter, and the announcement
is explicit about why: it lets a program be encoded as a *type* and interpreted by whichever context
runs it, which is the technique Hypershell is built on and the reason the crate exists. The same
parameter doubles as a dispatch key for API handlers.

**`derive_delegate` in `#[cgp_component]`** auto-generates the `UseDelegate` dispatcher impl for a
component generic over a parameter, removing boilerplate that had been written by hand. The
announcement shows it on `CanRaiseError<SourceError>`, which is still how CGP's own error components
are defined.

**`#[wrap_provider]` in `cgp_preset!`** lets a preset's `Provider` type be wrapped — in practice in
`UseDelegate` — so that a table of non-provider mappings becomes a valid delegation target. This is
what made presets usable for generic dispatch rather than only for component wiring.

Smaller items: `Char` can be formatted statically without a `self` value, opening the way to
recovering a runtime string from a type-level one; inline Rust documentation is added for common
constructs; and two macro-hygiene fixes land, including using `__Self__` rather than `T` in generated
preset code to avoid clashing with a user's own generic parameter.

## What it changed or removed

Nothing was removed. All four items are additions.

## How it relates to v0.8.0

**Current and much expanded.** The [handler family](../cgp/concepts/handlers.md) is now organized
along three axes rather than being three loose components:
[`Computer`](../cgp/reference/components/computer.md) gained by-reference and async variants,
[`TryComputer`](../cgp/reference/components/try_computer.md) filled the fallible-synchronous slot, and
[`Handler`](../cgp/reference/components/handler.md) settled as the async fallible case with
[`Producer`](../cgp/reference/components/producer.md) as the input-free one. The combinators that
compose them — [`PipeHandlers`, `ComposeHandlers`, and the `Promote*` lifts](../cgp/reference/providers/handler_combinators.md) —
came later, as did the [dispatch combinators](../cgp/reference/providers/dispatch_combinators.md) and
[monadic composition](../cgp/concepts/monadic-handlers.md). The `Code` parameter's role in encoding a
language as types is [type-level DSLs](../cgp/concepts/type-level-dsls.md), worked end to end in the
[shell-scripting DSL example](../examples/shell-scripting-dsl.md).

Static formatting of a type-level string grew into
[`StaticFormat` / `StaticString`](../cgp/reference/traits/static_format.md) in [v0.5.0](v0-5-0.md),
which is what lets a generic provider hand a field name to a library as a real `&'static str`.

**Changed since.** `CanHandle` as this release defines it —
`CanHandle<Code: Send, Input: Send>: HasAsyncErrorType` — no longer type-checks: `HasAsyncErrorType`
and the `Async` trait behind it were removed in [v0.5.0](v0-5-0.md), and the component now imports its
error type with [`#[use_type]`](../cgp/reference/attributes/use_type.md) while the `Send` guarantee is
recovered where it is needed, per [send-bounds](../cgp/concepts/send-bounds.md). `Char` was renamed
[`Chars`](../cgp/reference/types/chars.md) in the same release.

**Removed.** `#[wrap_provider]` went with the rest of the preset system in [v0.8.0](v0-8-0.md);
grouping wirings is now done with [namespaces](../cgp/concepts/namespaces.md), and the
`UseDelegate`-wrapping this attribute existed for is handled by the `open` statement of
[`delegate_components!`](../cgp/reference/macros/delegate_components.md).

**Demoted.** [`#[derive_delegate]`](../cgp/reference/attributes/derive_delegate.md) and
[`UseDelegate`](../cgp/reference/providers/use_delegate.md) still work, and CGP's own error and
handler components are still defined with them, so they are constructs an agent reads regularly. For
new code, [dispatching-per-type](../cgp/guides/dispatching-per-type.md) directs the `open` statement
instead.
