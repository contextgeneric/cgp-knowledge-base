# CGP v0.7.0

The ergonomics release, and the most recent shipped version. It introduces the attribute suite that
defines how CGP is written today — `#[cgp_fn]`, `#[implicit]`, `#[uses]`, `#[extend]`,
`#[use_provider]`, `#[use_type]` — and removes `#[cgp_context]`, the last of the scaffolding that made
a CGP context look unlike a struct.

- **Tag** — [`v0.7.0`](https://github.com/contextgeneric/cgp/releases/tag/v0.7.0), 28 February 2026
- **Announcement** — [Supercharge Rust functions with implicit arguments using CGP v0.7.0](https://contextgeneric.dev/blog/v0.7.0-release),
  documented at [website/blog/v0-7-0-release.md](../website/blog/v0-7-0-release.md)
- **Changelog** — the topmost entry in
  [CHANGELOG.md](https://github.com/contextgeneric/cgp/blob/main/CHANGELOG.md), but **headed
  "v0.6.2 (2026-03-01)"**: the release was renumbered to v0.7.0 once its breaking changes were
  counted, and the heading was never corrected. Read it as v0.7.0.
- **Relation to today** — the closest release to current. Its features are unchanged in v0.8.0 apart
  from one separator character.

## What it introduced

**`#[cgp_fn]` with `#[implicit]` arguments** turns a plain function into a context-generic capability
whose marked arguments are fetched from the calling context's fields rather than passed by the caller.
A struct opts in with `#[derive(HasField)]` and nothing else. This is the lowest-ceremony entry point
CGP has ever had, and it is what the site's tutorials now teach first.

**Four attributes replace hand-written bounds.** `#[uses]` imports another CGP capability so a
function or provider can call it on `self` without knowing its requirements; `#[extend]` does the same
while re-exporting it, which the announcement frames as the `pub use` to `#[uses]`'s `use`;
`#[use_provider]` fills in the stray `Self` argument on an inner provider's bound, so a higher-order
provider's dependency reads like an ordinary one; and `#[use_type]` imports an abstract associated
type as a bare alias, removing `Self::` from every use site. `#[implicit]` also becomes available
inside `#[cgp_impl]`, which removes the getter-trait layer from provider implementations entirely.

The announcement pairs these with a section answering the objection the word "implicit" invites.
Against Scala's implicit parameters, it argues three differences: resolution scope, since CGP resolves
only from a field on `self` rather than from a layered implicit scope; unambiguity, since CGP matches
on *name and type* where Scala matches on type alone, and Rust forbids duplicate field names; and
transparency, since every `#[implicit]` expands mechanically into a `HasField` bound and a `get_field`
call.

## What it changed or removed

**`#[cgp_context]` is removed**, following its deprecation in [v0.6.0](v0-6-0.md). A context is now an
ordinary struct with a `delegate_components!` block, and the `{Context}Components` provider struct no
longer exists.

**The consumer-trait blanket impl is simplified** to `Context: Greeter<Context>`, dropping the
`DelegateComponent` lookup because the provider trait's own blanket impl already performs it. One
consequence is noted honestly: with both traits in scope, a static method call can become ambiguous,
since a context wired through `delegate_components!` is also its own provider. Calls through `self`
are unaffected.

**`check_components!` and `delegate_and_check_components!` change syntax.** The `Name for Context`
form is replaced by a bare context name with an optional `#[check_trait(...)]` attribute, and both
gain `#[check_params]` and `#[skip_check]`. The default check trait name changes accordingly.

**Owned getter and implicit values require `Copy` rather than `Clone`**, so an expensive value is
never silently cloned into an owned argument.

**Two names go.** The `{Type}Of` alias is dropped from `#[cgp_type]`, superseded by `#[use_type]`, and
`ProvideType`/`TypeComponent` are renamed `TypeProvider`/`TypeProviderComponent` to match the
convention `#[cgp_type]` established.

One bug fix: `#[cgp_type]` when an associated type carries a self-referential bound.

## How it relates to v0.8.0

**Almost entirely current.** [`#[cgp_fn]`](../cgp/reference/macros/cgp_fn.md),
[`#[implicit]`](../cgp/reference/attributes/implicit.md),
[`#[uses]`](../cgp/reference/attributes/uses.md),
[`#[extend]`](../cgp/reference/attributes/extend.md),
[`#[use_provider]`](../cgp/reference/attributes/use_provider.md), and
[`#[use_type]`](../cgp/reference/attributes/use_type.md) all exist as described, and four guides
prescribe them: [reading-context-fields](../cgp/guides/reading-context-fields.md),
[declaring-dependencies](../cgp/guides/declaring-dependencies.md),
[capability-supertraits](../cgp/guides/capability-supertraits.md), and
[importing-abstract-types](../cgp/guides/importing-abstract-types.md). The renamed type component is
[`HasType` / `TypeProvider`](../cgp/reference/components/has_type.md), and the checking syntax is
current in [`check_components!`](../cgp/reference/macros/check_components.md).

**One character changed.** `#[use_type(HasScalarType::Scalar)]` became
`#[use_type(HasScalarType.Scalar)]` in [v0.8.0](v0-8-0.md) — a `.` where the announcement writes `::`.
This is the single most likely thing to be copied wrong from that post, because everything around it
still compiles. v0.8.0 also added the equality form,
`#[use_type(HasErrorType.{Error = AppError})]`, which pins an abstract type to a concrete one.

**Three things arrived after it.** [Namespaces](../cgp/concepts/namespaces.md) did not exist, so the
announcement's wiring examples show flat tables that a real application would now group. The `open`
statement did not exist, so nothing in it addresses
[dispatching-per-type](../cgp/guides/dispatching-per-type.md). And
[`cargo-cgp`](../cargo-cgp/README.md) did not exist, so its guidance is silent where current advice
would lead with `cargo cgp check`.

**One slip in the announcement, not in the release.** Its `HasScalarType` example declares
`type Scalar: Mul<Output = Scalar> + Copy;`, naming `Scalar` bare inside its own definition where
`Self::Scalar` is required. That syntax never worked.
