# CGP v0.6.1

A focused three-feature release, and the one whose contents have aged best: implicit context types in
`#[cgp_impl]`, the `#[check_providers]` attribute for isolating a broken layer of a composed provider,
and associated types declared directly in getter traits. All three are current.

- **Tag** — [`v0.6.1`](https://github.com/contextgeneric/cgp/releases/tag/v0.6.1), 1 February 2026
- **Announcement** — [CGP v0.6.1 Release: Improving Ergonomics and Debugging](https://contextgeneric.dev/blog/v0-6-1-release),
  documented at [website/blog/v0-6-1-release.md](../website/blog/v0-6-1-release.md)
- **Changelog** — [v0.6.1](https://github.com/contextgeneric/cgp/blob/main/CHANGELOG.md)
- **Relation to today** — all three features survive unchanged; only the surrounding idiom has moved.

## What it introduced

**Implicit context types in `#[cgp_impl]`.** A provider that previously had to declare
`impl<Context> Greeter for Context where Context: HasName` can now write
`impl Greeter where Self: HasName` and let the macro insert the parameter. The announcement's argument
for why this matters is worth keeping: the generic parameter was cognitive overhead unrelated to the
logic, and removing it makes a provider read like a method on a class — which is the shape a developer
arriving from an object-oriented background already knows.

**`#[check_providers(...)]`** changes what a `check_components!` block asserts, from "this *context*
can use this component" to "each of these *providers* is a valid provider for this component and
context." That distinction is what makes a composed provider debuggable: with
`ScaledArea<RectangleArea>` wired to a context, a plain check reports the composition as broken
without saying which layer failed, while checking `RectangleArea` and `ScaledArea<RectangleArea>`
separately localizes a missing field to the inner provider alone.

**Associated types in getter traits.** A getter whose return type should vary per context previously
needed a separate `#[cgp_type]` trait alongside it. It can now declare `type Name: Display;` directly
and have the concrete type inferred from the field, for both `#[cgp_auto_getter]` and `#[cgp_getter]`.

## What it changed or removed

Nothing. This is a purely additive release, and the only backward-compatibility note is that the
explicit `impl<Context> ... for Context` form continues to work.

## How it relates to v0.8.0

**All three are current.** The implicit context form is what
[`#[cgp_impl]`](../cgp/reference/macros/cgp_impl.md) documents as the preferred header, and
[writing-providers](../cgp/guides/writing-providers.md) prescribes omitting `for Context` except where
a lifetime or higher-ranked bound forces it to be named.
[`#[check_providers]`](../cgp/reference/macros/check_components.md) is documented within
`check_components!`, the technique it enables is the playbook in
[check traits](../cgp/concepts/check-traits.md) and the [debugging guide](../cgp/guides/debugging.md),
and the error class it diagnoses has its own catalog entry as
[higher-order-provider-layer](../cgp/errors/checks/higher-order-provider-layer.md). Getter associated
types are covered in [`#[cgp_auto_getter]`](../cgp/reference/macros/cgp_auto_getter.md) and
[`#[cgp_getter]`](../cgp/reference/macros/cgp_getter.md).

**The surrounding idiom moved one release later.** Everything the announcement writes as a `where`
clause has an attribute form now: `Self: HasRectangleFields` became
[`#[uses(...)]`](../cgp/reference/attributes/uses.md) and `InnerCalculator: AreaCalculator<Self>`
became [`#[use_provider(...)]`](../cgp/reference/attributes/use_provider.md), both in
[v0.7.0](v0-7-0.md); see [declaring-dependencies](../cgp/guides/declaring-dependencies.md). The getter
trait in the running example would today usually be replaced entirely by
[`#[implicit]`](../cgp/reference/attributes/implicit.md) arguments, and `Self::Name` would be imported
as a bare alias with [`#[use_type]`](../cgp/reference/attributes/use_type.md). The
`check_components! { CanUseRectangle for Rectangle { ... } }` syntax changed in
[v0.7.0](v0-7-0.md) to a bare context name with an optional `#[check_trait(...)]` attribute.

**One tool arrived after it.** The debugging story `#[check_providers]` opened is now led by
[`cargo-cgp`](../cargo-cgp/README.md), adopted in [v0.8.0](v0-8-0.md), which rewrites the diagnostic
rather than only localizing it. The two are complementary: run `cargo cgp check` first, and reach for
`#[check_providers]` when a composition needs bisecting.
